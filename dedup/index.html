Deduplicador exato · CLI

Dedup

Duplicata é só o que tem os mesmos bytes. Nada de semelhança, nada de palpite — e toda ação que destrói começa recusando-se a agir.

Linguagem Go 1.25+
Hash BLAKE3
Plataforma Linux · Windows
Licença MIT

Dedup percorre as pastas que você aponta, agrupa os arquivos por tamanho, calcula BLAKE3 só de quem tem companhia nesse tamanho, e escolhe um de cada grupo para ser o canônico. Os outros são cópias. O que fazer com elas é escolha sua — e toda escolha destrutiva começa em modo de ensaio, sem tocar em disco.

❖
I · Comandos

Quatro verbos

report · scan

Descobre e relata. Não encosta em nenhum arquivo. É por onde se começa, sempre.

copy-unique

Copia únicos e canônicos para um diretório novo, achatado. O original fica intacto onde está.

move-duplicates

Move só as cópias para uma quarentena. O canônico permanece no lugar.

delete-duplicates

Apaga só as cópias. Exige --yes explícito e --dry-run=false.

III · Segurança

A recusa em agir

Todo comando destrutivo nasce em --dry-run=true. Rodar sem mais nada mostra o que seria feito e termina sem escrever nada.

ensaio 
dedup delete-duplicates ./fotos
# lista o que apagaria — e não apaga
para valer 
dedup delete-duplicates ./fotos --yes --dry-run=false

As seis invariantes

Verificadas antes de qualquer ação tocar o disco. Violação aborta o plano inteiro, não o item.

#Garantia
1Nenhuma ação destrutiva alcança um canônico. Apagar ou mover o que foi eleito para ficar é impossível por construção.
2Em copy-unique, nenhum destino cai dentro de uma raiz de entrada. A saída nunca contamina a varredura.
3Todo caminho de destino é único no plano. Duas ações nunca disputam o mesmo arquivo.
4A cópia recusa sobrescrever destino com bytes diferentes. Divergência falha alto, não em silêncio.
5Delete recusa remover diretório. Sempre, sem exceção.
6A sequência do plano é contígua de 1 a N. Buraco na numeração aborta a execução.
Irreversível

delete-duplicates apaga de verdade. Não há lixeira, não há desfazer. Rode o ensaio, leia a lista, e só então acrescente --yes --dry-run=false.

IV · Canônico

Quem fica

Dentro de um grupo de arquivos idênticos, um é eleito canônico e os demais viram cópias. A eleição é determinística — as mesmas entradas elegem sempre o mesmo vencedor.

CritérioRegra
1º · idadeVence o mtime mais antigo. O original costuma ser o primeiro a existir.
2º · desempateOrdem lexical do caminho, quando os mtime são exatamente iguais.

A seleção devolve junto a razão da escolha e os tempos dos derrotados, de modo que a decisão seja auditável e não apenas confiável.

Determinismo testado

run_test.go trata o determinismo como regressão: mesma árvore de entrada precisa produzir saída byte a byte idêntica. É o que torna o Dedup utilizável em CI.

VI · Auditoria

A trilha

Toda execução grava um JSONL antes de agir — write-ahead. Se o processo morrer no meio, a trilha já registrou a intenção, e dá para reconstruir o que havia sido planejado.

caminho 
./.dedup-audit/<started_at>.jsonl

Em modo de ensaio, cada item entra com status=planned e o disco permanece intocado. A trilha do ensaio é, portanto, o plano exato que a execução real seguiria.

VII · Forma

O pipeline

cmd/dedup é uma casca fina sobre internal/cli. Todos os comandos descem pelo mesmo caminho em internal/pipeline.Run:

EtapaO que faz
scan.WalkPercorre as raízes e coleta os candidatos, respeitando filtros.
compare.PreSizeAgrupa por tamanho. Tamanho que aparece uma vez só não pode ter irmão idêntico — vira único sem nunca ser lido.
internal/hashBLAKE3 em streaming, só sobre quem sobreviveu ao agrupamento por tamanho.
canonical.SelectElege o canônico de cada grupo e registra a razão.
actions.PlanMonta o plano numerado de 1 a N.
actions.CheckInvariantsVerifica as seis garantias. Falhou, nada é executado.
actions.ExecuteAplica o plano, gravando a trilha item a item.
Por que o agrupamento por tamanho vem antes

É o que faz o Dedup ser rápido em árvores grandes. Um arquivo cujo tamanho aparece uma única vez na entrada não pode, por definição, ter um gêmeo byte a byte em lugar nenhum — então ele nunca é lido para hash.

III · Pipeline

Etapas

fluxo 
scan.Walk
  └─ respeita filters.include / exclude / ext, follow_symlinks

compare.PreSize
  └─ agrupa por tamanho
  └─ tamanho singular => único, nunca lido para hash

internal/hash  (BLAKE3, streaming)
  └─ só sobre grupos de tamanho com 2+ membros

canonical.Select
  └─ 1º mtime mais antigo
  └─ 2º ordem lexical do caminho
  └─ devolve SelectionReason + tempos dos derrotados

actions.Plan
  └─ itens numerados 1..N

actions.CheckInvariants      <-- antes de qualquer escrita
  └─ violação aborta o plano inteiro

actions.Execute
  └─ grava JSONL write-ahead por item
  └─ dry-run => status=planned, disco intocado
IV · Invariantes

Verificadas em código

Origem: internal/actions/invariants.go. Cada uma devolve erro que interrompe a execução.

json 
[
  { "id": 1,
    "rule": "no destructive action targets a canonical path",
    "applies_to": ["delete", "move"],
    "error": "invariant: {kind} action on canonical {path}" },

  { "id": 2,
    "rule": "no copy destination lies inside any input root",
    "applies_to": ["copy-unique"],
    "error": "invariant: copy destination {dst} is inside root {root}" },

  { "id": 3,
    "rule": "every destination path in the plan is unique",
    "applies_to": ["all"],
    "error": "invariant: duplicate destination {dst}" },

  { "id": 4,
    "rule": "copy refuses to overwrite a destination with different bytes",
    "applies_to": ["copy-unique"],
    "behaviour": "fails loudly, never silently" },

  { "id": 5,
    "rule": "delete refuses to remove directories",
    "applies_to": ["delete-duplicates"],
    "behaviour": "always, no exception" },

  { "id": 6,
    "rule": "plan seq is contiguous 1..N",
    "applies_to": ["all"],
    "error": "invariant: plan seq is not contiguous 1..N" }
]

Há ainda uma validação de configuração que roda antes: output.dir não pode estar dentro de nenhuma raiz de entrada.

Cada chave tem contraparte em variável de ambiente com prefixo DEDUP_, e uma flag de linha de comando. A flag vence a variável, que vence o YAML, que vence o padrão.

VI · Determinismo

Contrato de saída

A saída é determinística por projeto, e isso é verificado como regressão em run_test.go. Para um agente, a consequência prática:

GarantiaImplicação
Mesma entrada, mesma saídaDiffs de relatório são significativos: mudou o relatório, mudou a árvore.
Canônico estávelRodar duas vezes nunca elege vencedores diferentes.
Sufixo de colisão estável_1, _2 seguem ordem fixa, não ordem de descoberta.
Ensaio == execuçãoO plano do --dry-run é exatamente o que a execução real aplicaria.
VII · Limites

O que ele não é

Não fazPorquê
SimilaridadeDuplicata é identidade de bytes. Imagem redimensionada não é cópia.
Transformação de conteúdoNão normaliza, não converte, não re-encoda antes de comparar.
OCR ou leitura semânticaFora de escopo por decisão de projeto.
Lixeira ou desfazerdelete-duplicates apaga. A proteção é o ensaio, não a reversão.
Para agentes

Nunca invoque delete-duplicates --yes --dry-run=false sem ter apresentado antes ao usuário a saída do ensaio e obtido confirmação explícita. A flag --yes suprime a pergunta do programa, não a necessidade de perguntar.
